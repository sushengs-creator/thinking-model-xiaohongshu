# 七图文案：起草、审核、修改与定稿

本文件管理七张图的文字及其编辑流程。小红书发布正文另按正文规范制作；设计说明、审核记录、字数说明不得混入上图文字。
默认自动完成起草、独立审核、修订、定稿、制图、验收和打包；中间稿及审核结果保存为工作文件，不等待用户逐步确认。最终聊天交付规则见 [delivery.md](delivery.md)。
以下流程以一个模型编号为单位执行。多篇定稿须分别完成完整七页稿、审核、修订和七张图片，不能把多篇共用七页或将不同模型的内容混入一组。每个模型独立保存版本与审核记录，共用的七张 049 母版保持只读。

## 一、依据与固定页面任务

- 以已定稿文章、准确的模型编号及名称为内容依据，不从旧案例复制结论或数据。
- 文件与工具边界遵循 [SKILL.md](../SKILL.md)。必要输入或母版确实缺失时如实说明，不自行寻找替代素材或编造内容。
- 必须逐页对照 `assets/masters/049-p01.jpg` 至 `049-p07.jpg`（相对于Skill根目录），按对应页的布局承载新内容，不能只抽取配色或“类似风格”。
- 用户当前指定的 049 母版优先于旧提示词中的模块数量。例如 P4 为四行卡片，P5 为两个误解卡片加一组对照，不能套回“三场景”“三误解”。四行优先放四个有依据的场景；只有三个可靠案例时，第四行可明确承载共同模式或判断提示，不编造第四例。
- 页面任务固定；页面中的问题、观点、案例、方法及示意图含义随新模型更换。049 的数字、说法及“失败条件”等主题内容不是通用文案。

| 页 | 页面任务 | 对应母版的文案承载结构 | 读者验收问题 |
| --- | --- | --- | --- |
| P1 | 痛点 | 编号、模型名、痛点问句、中心冲突示意、双例卡、底部收束 | 我为什么要继续看？ |
| P2 | 定义 | 提问、一句话定义、两种情况对照、链路、金句 | 这个模型到底讲什么？ |
| P3 | 机制 | 提问、中心对象、四个关系节点、关系标注、底部总结 | 它如何发生或运作？ |
| P4 | 场景 | 四行卡片、共同模式、后果、点破句 | 这在生活或工作中是什么样？ |
| P5 | 边界 | 两个误解卡、两侧对照、核心区别、边界句 | 什么不能据此推出？ |
| P6 | 方法 | 三张行动卡、可填写工具卡、方法总结 | 下次遇到时，第一步怎么做？ |
| P7 | 收束 | 提问、解释、主题示意、思考卡、核心金句、行动入口 | 我该记住什么，并从哪里开始？ |

模板见 [page-copy-template.md](page-copy-template.md)。固定的系列标识、页码、页脚和印章按视觉规范处理，不复用旧模型编号与名称。

## 二、起草

1. 先读完文章，提取核心含义、适用问题、机制、必要边界和可执行方法；再确定这组图唯一的核心记忆点。
2. 逐页查看对应母版，按现有模块容量组织内容。每页只承担一个核心任务，其他内容为它服务。
3. P1 的痛点必须是模型能回答的问题；P2 在第一次出现必要术语时作通俗解释；P3 的箭头必须有逻辑含义。
4. P3 可解释心理机制、系统机制、判断过程或模型的运行方式，不把所有模型都写成“你为什么会这样”。四个节点可以是过程、分支或要素，不能为了四个框伪造四步因果。
5. P4 使用具体人物处境、行为和结果，四行内容共同指向同一机制。可以使用明确属于说明用途的假设例，不得伪装成真实事件；可靠案例只有三个时，第四行可作为共同模式或判断提示。
6. P5 澄清最容易产生的两类误解，通过对照说明真正的区别；不套用与本模型无关的边界内容。
7. P6 每项方法包括动作和具体表达或做法；可填写工具卡必须能实际使用。不能用“提高认知”“保持理性”等口号代替动作。
8. P7 收束前文，不再增加未经解释的新理论。读者能立即回答一个问题、填写一个空格或完成一个小动作。
9. 标题优先使用具体问句、反问或冲突表达，避免“定义”“案例”“方法”作为唯一标题；无需强迫七页全部使用问号。
10. 文字短、清楚、有节奏，避免大段正文和同义重复。文案太满时先删减、合并、移入发布正文，不能靠不断缩小文字解决。

## 三、审核

审核必须基于完整七页稿，作为与起草分开的独立审稿步骤完成。先诊断，再给可落实到具体页面的修改办法，不把“更有感染力”“再简洁一点”当成完成审核；提出建议后自动修订并复核，不把建议交给用户代替执行。

### 整体诊断

- 用简短文字指出当前最影响阅读的主要问题及其所在页面。
- 检查是否形成“痛点 → 定义 → 机制 → 场景 → 边界 → 方法 → 收束”的递进。
- 检查标题、发布正文与七图是否对同一模型作出一致解释。
- 检查核心记忆点是否准确，是否出现为追求传播效果而夸大结论、鸡汤化或偷换概念。

### 逐页检查

| 维度 | 通过条件 |
| --- | --- |
| 内容准确 | 概念、因果、条件和范围成立；简化没有改变原意 |
| 来源可信 | 真实数据、历史案例、引语有依据；假设示例身份明确 |
| 任务单一 | 每页核心任务清楚，模块之间没有争抢主旨 |
| 初读易懂 | 必要术语已解释，代词有指向，标题和正文互相回答 |
| 图文关系 | 机制边和对照维度成立；图形不是装饰性地重复文字 |
| 方法可用 | 有具体动作、适用场景和必要判断条件 |
| 母版适配 | 内容逐页落入指定母版，没有恢复旧版模块数量或堆叠新增卡片 |
| 视觉密度 | 放大词明确，次要内容可弱化，冗余有删除去向 |

逐页问题记录至少包含：页码、原句或模块、问题、读者会如何误解或卡住、具体改法。对涉及事实、概念、边界的关键问题，修改后必须复核，不能只换措辞。

### 审核记录保留项

- 整体诊断。
- 逐页问题与改法。
- 修改后的完整七页稿。
- 每页三个额外标题备选，仅供编辑留档；执行者自行选定合适标题，不形成等待用户选择的节点，也不把备选混入最终上图稿。
- 删除、弱化或移入发布正文的内容及理由。
- 一句话核心记忆点。

## 四、修改与复核

1. 按审核意见修订完整七页，不只列建议。保留上一轮已经有效且与当前规范一致的改进。
2. 同时处理连带影响：定义变更后检查机制、案例、边界和方法；标题变更后检查正文是否实际回答了问题。
3. 检查案例参数是否只是说明示例。不得把 049 的“30%”“15%”“三个月”等写成适用于其他模型的通用阈值。
4. 用正常阅读顺序通读七页，再逐页对照母版检查信息量。P5 和 P7 容易因补充解释过多而拥挤，应重点删掉重复结论。
5. 复核上轮问题是否解决；未解决的事实或概念问题不能被“已优化”掩盖。
6. 用简短版本号管理文案，如 `v1`、`v2`。一份七页文档即可保留版本及必要修订摘要，不引入数据库或复杂状态系统。

## 五、定稿与制图交接

定稿至少满足：编号名称一致、七页任务完整、核心含义准确、关键审核问题已解决、上图文字完整、设计说明已分离、母版对应清楚。

- 默认依据完整流程授权，在关键审核问题解决后自行定稿并直接出图；不询问是否启动、是否定稿、是否继续或逐页是否确认。文案审核与图片验收均为内部执行步骤。
- 用户只要求起草、审稿或修改时，完成该环节即可；不要自动扩大为制图。
- 仅当用户当轮明确要求确认时，才在指定节点提交具体可审阅稿和需要决定的事项。必要输入缺失或工具真实受阻且无法继续时，如实报告具体障碍，不以自动执行为由伪造完成状态。
- 在定稿页首记录：模型编号与名称、文字版本、定稿依据（默认完整流程授权；若用户明确要求确认则记录其确认）、使用的逐页母版。
- 将“上图文字”冻结为本模型制图唯一文字来源；设计说明只指导生成，不进入图片。
- 每张图只使用对应模型、对应页的冻结文字，不把其他模型内容、失效旧稿或标题备选混入图片。续做时按 [delivery.md](delivery.md) 比对每页可见文字与版面要求，保留真实生成版本和当前复核版本。每个模型先验收自己的 P1，再制作其 P2—P7。
- 后续改字时更新版本，并重新制作受影响的页面；若改变全组结论或公共标识，检查全部七页。
- 提示词、文案及审核通过不等于图片完成。图片需要实际生成，并逐页核对文字、关系、版式和页码后才能交付。
- 默认将本模型的定稿、审核与修订记录、七张验收后的图片一并收入独立制作包。单篇最终给一条 ZIP 下载链接；多篇按编号数值升序，每个模型给一条独立 ZIP 下载链接，不以总 ZIP 代替各篇制作包，不逐页贴图或展示中间稿。

## 六、资料解释边界

2026 年 8 月的优化提示词提供可复用审核方法，原件附带的“069 运气—技能连续体”待优化案例已从公开版移除。不要把历史数字、具体例子、金句、连续体图形或 P5/P6 的案例顺序固化为通用规则。

旧图片规范中的“三场景”“三误解”“孤岛测试”“学习→入口→羊群”等，分别属于历史模板或具体主题。与本轮 049 逐页母版冲突时，采用当前指定母版及本文件的页面任务。
