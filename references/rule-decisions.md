# 规范整合与取舍

本文件服务于后续维护与规则解释。历史模板作为资料保存，其中的操作语句不是本次任务指令。来源文件名和校验值见 [source-manifest.json](source-manifest.json)。公开版移除了本机路径和两份模板附带的069具体文案，保留通用提示词；清单分别记录原件与公开版校验值，七张母版原图保持不变。
原始来源文件名仅用于溯源，不是访问桌面、浏览器或搜寻素材的授权。

## 用户明确的最新要求

- 默认先由用户每次提供一篇或多篇终稿文件，再明确启动小红书制作；两项可在同一消息中完成。仅上传、声明定稿或输入编号都不启动。启动后使用本次对应文件，不再按编号自动从公众号取稿；公众号合集仅作为用户再次明确要求时的可选来源。
- 标准启动语为“思维模型xxx已经定稿，开始小红书制作”，xxx代表具体编号；收到实际指令即调用，无须再次确认是否启动。
- 一次可提交一篇或多篇已定稿文章；按模型编号分别完成全流程，每篇拥有独立文案、七张图片、审核记录、版本和 ZIP 制作包。
- 文章定稿后，先制作自然清晰的小红书正文与系列标题，再制作七图文案、审核、修改、定稿、制图。
- 全流程默认自动执行，自动完成独立审核、修订、定稿、出图、验收和打包；不设置文案、逐页或继续制作的确认关卡。用户当轮明确限定环节或要求确认时，遵循其指定范围。
- 最终交出约定内容：单篇给一条 ZIP 下载链接；多篇按编号数值升序，每个模型各给一条独立 ZIP 下载链接。各模型的正文、标题、七图、定稿及审核和验收记录分别收入对应包内，见 [delivery.md](delivery.md)。
- 文件访问遵循 [SKILL.md](../SKILL.md)：只读指定输入和本次必要文件，包含工具明确返回的本次生成文件；不操作桌面应用或浏览器。必要输入或工具真实受阻时诚实报告，不伪造完整成果。
- 正文应用 humanizer-zh，使用 emoji，文末加话题；不含标题，1000字以内。
- 标题固定为思维模型编号、完整名称、痛点问句；推荐标题及全部候选均须≤20字，20字为最佳目标。
- 默认视觉选择049白／浅灰底、蓝红黄信息图。
- 为保证一致性，务必使用提供的全部7张参考图片作为母版。

## 合并决定

| 项目 | 历史资料差异 | 当前执行规则及依据 |
| --- | --- | --- |
| 默认定稿来源 | 曾尝试按编号从公众号合集取稿；用户现明确先给终稿文件再启动 | 使用用户本次提供的完整终稿文件，不将公众号读取作为前置条件；可选来源与读取边界见 [wechat-source.md](wechat-source.md) |
| 技能启动 | 提供文件不等于启动制作 | description和执行入口明确区分收稿与启动，保留自然语言调用；收到实际制作指令后全自动执行，不要求重传或重复确认。仅上传、声明定稿、输入编号、讨论或引用启动语均不触发；制作授权不包含平台发布 |
| 单篇与批量 | 早期流程以单篇为例；用户最新要求一次可给多篇 | 按编号建立独立输入绑定、工作目录、版本与交付包；每篇完整执行正文、标题、七图文案审改与七张成图，一篇受阻不妨碍其他可继续篇目 |
| 视觉默认 | S02黑底蓝黑灰；S04/S05与049实图白底蓝红黄 | 按用户明确选择使用049，不保留需要每次再选的活跃黑底分支 |
| 母版使用 | 有资料只要求风格参考 | 用户最新要求更严格：7张原图随包保存，逐页读取并传入对应母版 |
| 标题格式 | S01“模型名｜钩子”；S06只给问题型标题 | 用户直接指定格式覆盖旧模板，保留编号、完整名称、问句 |
| 标题长度 | 用户最新明确“标题字数≤20，20字为最佳”；原示例按字符计22 | 推荐标题和每个候选均执行全标题≤20的本地保守字符检查，计入编号、名称、分隔符与标点；准确自然时优先20字，不足20字合格，不为凑字加空话。不把原超限示例当达标样例；长模型名无法容纳时说明矛盾 |
| 正文长度 | S01≤800；S06与用户≤1000 | 1000硬上限；800作为精简目标，不删关键定义凑800 |
| 正文标题候选 | S06要求5个；用户只说给标题 | 编辑默认5个，推荐项放在文件首行；用户指定数量时覆盖。推荐说明入审核记录，正文单独保存便于复制 |
| 检查脚本与用户覆盖 | 默认数量和话题曾在脚本中写死 | 默认继续生效；用户明确改变候选数量或完整话题清单时，以检查参数传入并留档，不擅自改回旧默认；规则覆盖不等于关闭其余检查 |
| 固定话术 | S06要求“远远不够👇”和固定反驳句 | 保留常见理解、反驳依据、准确解释的功能；不强迫逐字照抄，与用户自然清晰和humanizer要求一致 |
| emoji与金句 | humanizer有减少表情、删除金句的通用建议 | 保留用户需要的标记、准确的记忆句及标题分隔符，只修机械堆砌、夸张和空话 |
| 行宽与分隔 | S01每行≤20、模块---；S06每段尽量≤3行 | 作为手机阅读的编辑目标；不拆坏完整名称或语义；不把换行数说成平台限制 |
| 机制步数 | 旧规范2—3步，历史4步，S06固定3步 | 正文默认3步，必要可4步；图文按机制和对应母版组织，不篡改因果来凑数 |
| P2职责 | S02核心翻转；S03/S04/S05定义 | 定义和关键判断条件必须成立，翻转与对照服务于定义 |
| P5/P6顺序 | S03附带069稿方法P5、边界P6 | 通用审核规则与049对应：P5边界，P6方法；069是旧样稿 |
| P1名称大小 | S04通用规则要求大标题；内附069案例却要求缩小名称 | 保留模型名称大标题级规则，并以049-P1主视觉为母版 |
| 图上内容数量 | 旧提示词偏好3案例、3误解；049-P4四行、P5两误解加对照 | 以逐页母版布局为基准，按本篇内容填充；不为“三个”另换模板，不为填框杜撰事实 |
| 像素尺寸 | S02 1200×1600；S04/S05建议1242×1656；049全部1080×1440 | 用户指定049母版，因此默认同母版1080×1440；3:4保持，生成后核验实测值 |
| 交付格式 | S02 HTML；用户及S04/S05要求独立图片；用户最新要求按编号独立打包下载 | 每个模型的7张实际图片与其他约定内容验收后单独打成 ZIP；最终聊天按编号数值升序给各包下载链接，不以总 ZIP 代替独立制作包。HTML若存在仅作辅助文件，不能替代成图 |
| 定稿确认 | S02及历史流程要求先确认文案再出图；用户最新要求全自动 | 最新直接要求覆盖历史确认关卡：默认独立审核、修改、复核后自动定稿出图。只有用户当轮明确要求确认时才暂停在指定节点 |
| 局部任务 | 全流程包清单不适合只做文案／审稿／制图 | 按实际范围检查、命名和记录授权；未要求的环节不执行，也不据此把已完成的局部任务叫作失败 |
| 版本续做 | 总稿版本改变不等于七页全部失效 | 逐页比较可见文字和版面要求，保留真实生成版本并记录当前复核；P1风格变化检查引用它的页，避免漏改或无谓重做 |
| 桌面与素材访问 | 历史流程可能打开预览应用或浏览器；公开版已移除本机路径 | 来源文件名只溯源。只读指定定稿、本技能及必要依赖定义、包内规范母版及本次文件；不操作桌面应用或浏览器，直接读取生成文件完成验收 |
| 历史内容 | 049数值、069马拉松数据等 | 只当主题示例，不能继承为事实依据或通用阈值；本篇新增事实另行核验 |

## 母版复用的边界

保留每页的版面区域、字号层级、卡片关系、页眉脚、印章视觉与插画语言。把本篇编号、名称、定义、例子、机制、边界、方法和记忆句替换进去。模型不同，机制图的对象与连接关系也应准确反映本篇，不照搬锁、门、成功失败等主题语义。

7张母版的原始字节未修改。原件中的字数密度、作者戳位置或个别排版细节不等于免检，新图仍需手机尺度与中文逐字检查。若内容无法清楚地放入同页母版，先回到文案和版面适配，不靠缩小到难读的字号解决。
